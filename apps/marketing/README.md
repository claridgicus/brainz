# brainz-marketing

Static SvelteKit marketing site for brownmatter.ai, deployed to Cloudflare
Workers static assets.

## Commands

```sh
npm run dev      # vite dev
npm run build    # vite build (prerendered static site into build/) + regenerate build/sitemap.xml
npm run preview  # wrangler dev over the built assets
npm run check    # svelte-check
npm test         # scripts/check-build.mjs — post-build assertions (CTA links, no external assets, SEO head)
npm run deploy   # GATED: predeploy runs the marketing test subset first, then build + wrangler deploy
```

## SEO

- Every page renders `src/lib/components/Seo.svelte` exactly once — title,
  description, canonical, Open Graph + Twitter card, and schema.org JSON-LD
  (`Organization` + `WebSite` sitewide, plus per-page entities via the
  `schema` prop). Don't hand-write head tags on new pages; add a `<Seo …/>`.
- Social cards: `static/og.png` (1200×630) and `static/apple-touch-icon.png`
  are committed PNGs rendered from the HTML sources in `assets/` — edit the
  source, run `node scripts/generate-og.mjs` (needs Chrome), commit both.
- `build/sitemap.xml` is generated by `scripts/generate-sitemap.mjs` from the
  pages the build actually prerendered (so it exists only after a build, not
  in `vite dev`); `static/robots.txt` points crawlers at it.
- `scripts/check-build.mjs` fails the build gate if any prerendered page is
  missing the SEO head, the card PNGs are absent or the wrong size, or the
  sitemap drifts from the prerendered page set.

## Deploy is gated

`npm run deploy` cannot proceed unless the gate passes: the `predeploy` hook
runs `node ../../scripts/test-all.mjs --scope marketing` (svelte-check →
build → check-build). The full monorepo gate is `npm run test:all` at the
repo root — see `TESTING.md` there.
